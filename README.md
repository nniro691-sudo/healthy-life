# 山寺 · 清心一隅

单人版入口：https://nniro691-sudo.github.io/healthy-life/ 。

多人版入口：https://nniro691-sudo.github.io/healthy-life/multiplayer/ 。GitHub Pages 网页已连接 Sites 云端房间接口，无需 Render 绑卡。分享同一 `?room=...` 链接即可共同参拜、合十问候和回礼。

云端接口：`https://shan-si-multiplayer.tingzhang1119.chatgpt.site`。使用 D1 保存共享房间状态，短间隔同步位置和动作，通过数据库唯一索引防止拜垫重复占用。访客正常退出立即释放位置，断线 15 秒后过期；回到页面自动重连。当前验证双用户联机，未做 64 人满员压测。

`cloud-deployment/` 保存已发布后端源码及迁移；更新后端需通过 Sites 标准发布流程重新构建、同步和部署。`npm run build:pages` 同时构建两个版本：根目录单人版不连接后端，`multiplayer/` 通过 `VITE_ROOM_API` 连接云端接口。`node scripts/check-cloud-room.mjs` 验证公开双用户参拜、上香、互相问候和退出释放。原 Node/SSE 服务仍可独立部署。

两侧菩萨改用约 2.34 MB 的 Meshopt/WebP 压缩版（原约 12.21 MB），保持原模型细节和署名。主佛优先下载，佛像下载失败自动重试；网络较慢时显示下载状态，失败时可点击重新加载。心愿和修行计数仍只存本机，云端仅同步匿名人物状态及短时问候。

参考拜佛视频的寺庙修行应用。统一三维寺庙空间、实时角色、64 个地面拜垫与真实多人房间。原健康打卡页保留于 `满电健康打卡 v2.dc.html`。

## 本地开发

```sh
npm install
npm run dev
```

打开控制台显示的本地链接。手机或其他电脑连接同一局域网，使用控制台的 `Network` 地址。右上“同寺 N 人在线”可打开邀请面板并复制房间链接；本机访问时优先给出局域网地址。

同一服务、同一 `?room=...` 房间中的用户能互相看到。省略 room 时加入默认房间。每个标签页是独立匿名用户，不会用 NPC 或虚构数字冒充在线玩家。

## 生产运行

```sh
npm run build
npm start
```

Node.js 服务默认监听 `0.0.0.0:5173`，可使用 `PORT` 设置端口。服务同时提供 `dist/` 和多人接口；也可用 `npm run preview` 验证构建。

本地生产命令使用 Node/SSE 服务，反向代理需允许 SSE 长连接并关闭缓冲，房间保存在单进程内。当前公开网页使用上述 Sites/D1 共享后端，不需要部署这个 Node 服务；纯静态构建若未设置 `VITE_ROOM_API` 则无法同步多人。`render.yaml` 保留为可选的 Node 托管配置。

## 使用

- 点击地面 / WASD / 方向键 / 屏幕方向控制：前后左右行走；拖动可 360° 环顾，滚轮或双指缩放。方向以当前视角为准。
- 右侧“复位视角 / 左看 / 右看 / ＋ / －”可控制相机。相机会跟随人物，靠墙环顾时限制镜头位置。
- 佛殿摆放 64 个三维拜垫，点击空闲拜垫后走到相应位置，面向佛像自动参拜。
- 上香：进入佛殿后点击“上香”，人物走到香案、持香齐眉礼敬，并有飘散烟雾；完成动作后累计次数。
- 合掌、跪拜按钮会优先寻找最近的空闲拜垫；再次点击可停止。
- 合十问候：点击附近同修的人物或名字，人物会转向对方合十；对方收到提示，可点“合十回礼”。
- 拜垫占用由服务端校验，已被其他用户使用时会提示。用户离开、切换场景或停止后释放。
- 真实位置、方向、行走 / 合掌 / 跪拜动作与拜垫占用实时同步。离开当前场景的用户不会继续显示在原场景。
- 山门、庭院、佛殿和许愿树处于同一个三维空间；可以连续走入其他区域，位置标题随区域更新。侧栏可快捷到达，路线也可自动漫游。
- 三维木鱼支持手动、空格、自动敲击及速度、声音选择，木槌随敲击运动，可拖动查看器物。
- 三维念珠会自然流转；向下拨动、点击或选择“拨动一颗”累计一念，可开启自动持念和声音。以 108 念为一轮，视觉转动本身不增加次数。
- 心愿、修行计数与偏好保存在当前浏览器；多人接口仅同步匿名角色状态。
- Esc 关闭面板、停止修行和漫游。设置支持音量、清净模式、减少动态和画质。

## 结构与验证

- `src/monk.js`：人物造型、衣袖、合掌/跪拜/上香动作、持香与烟雾。
- `src/ritual-viewer.js`：三维木鱼、木槌、材质、念珠均匀流转和器物交互。
- `src/world.js`：三维相机、环顾、连续行走、参拜位置、远端角色显示。
- `src/temple.js`、`src/navigation.js`：建筑、庭院、山门、许愿树、地面、材质、边界和经过入口的走位。
- `src/cushions.js`、`src/mats.js`：拜垫几何和共享位置定义。
- `src/multiplayer.js`、`server/rooms.js`：SSE 广播、状态上报、房间与占用管理。
- `server/index.js`：生产入口；`src/main.js`、`src/style.css`：交互和响应式界面。

`npm test` 验证完整跪拜不穿地、拜垫透视点击、双连接动作同步、占用冲突和离线释放。`npm run build` 生成生产资源。详见 `docs/QA.md`。

当前为风格化三维网页应用。建筑、地面、柱梁、屋顶、庭院、人物与拜垫均为三维几何体；佛龛结合原有图像纹理面板和体积造型以保留金色细节。人物保持风格化造型，并非扫描级写实模型。尚未封装为微信小程序或原生安装包。

默认人物为初版的 50%，拜垫为初版的 72%，人物头部进一步调整比例，肩袖从胸背内部平滑连接，增加手掌和手指。房间连接上限配置为 64，但当前仅完成双用户联机验证，未完成满员性能压测。

室外使用本地生成的山林等距柱状全景 `public/assets/mountain-panorama.jpg` 和透明松枝 `public/assets/pine-canopy.webp`。全景跟随相机环顾，近处树木使用三维枝干与交叉叶片贴图，树冠附近限制镜头高度并淡出过近枝叶。素材提示词与检查结果见 docs/QA.md。

主佛采用高清透明底金身图像，固定放置在真实三维佛龛内，以保证眉眼、唇线、手指和衣褶的清晰度。此主像是项目通过内置 imagegen 生成的图像资产，不是扫描三维模型；侧面观看会呈现图像平面的透视。图像为 `public/assets/shakyamuni-gold-hd.webp`，生成提示词见同目录的 `.prompt.txt`。两侧菩萨继续使用 Minneapolis Institute of Art 的完整三维扫描（CC BY-SA 4.0），来源见 [模型署名](public/assets/models/CREDITS.md)。未使用的旧扫描和历史预览图已从当前版本删除，Git 历史仍可恢复。

主佛图像高度约 11.6 米，梁顶约 17.3 米、屋脊约 19.6 米。柱梁、上层窗格、藻井与佛龛同步增高。人物大小及世界行走路径保持原样。默认镜头保持约 1.65 米的人眼高度，走近高大佛像时自然仰视。

## 多人公网部署

通过 [Render 部署此仓库](https://render.com/deploy?repo=https://github.com/nniro691-sudo/healthy-life)，使用 `render.yaml` 中的免费 Node Web Service 配置。健康检查为 `/healthz`，整个站点由同一个服务提供，勿设置 `VITE_STATIC_DEMO=true`。仅运行一个实例以共享内存中的房间。Render 免费服务闲置后会休眠，首次唤醒需要等待。

部署成功后运行 `node scripts/check-public-room.mjs https://实际服务域名`，验证两个独立公网连接的跪拜、上香、拜垫占用、合十问候及离线释放。分享服务链接时保留相同的 `?room=...` 参数；HTTPS 代理后的邀请链接会保持 HTTPS。

资源精简：当前 public 资源约 4.4 MiB；主佛 WebP 约 0.48 MB，保留 1024×1536 和透明背景。闲置模型、旧场景照片和历史预览图共删除约 54 MB。两种版本共用源素材，各自生成独立静态目录；构建后自动清除临时中间目录。
